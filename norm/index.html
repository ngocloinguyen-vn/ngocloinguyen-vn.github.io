Normalization in R

Date: September 01, 2026

1. What is normalization?

Normalization is the process of adjusting raw sequencing counts to make samples with different sequencing depths comparable while minimizing technical variation that is unrelated to biological differences. In metabarcoding data, samples often contain different numbers of sequencing reads, so a sample with more reads may appear to have higher abundances simply because it was sequenced more deeply. Normalization corrects for this variation while retaining meaningful differences in community composition.


There are a few alternative normalization methods commonly used for microbiome or ecological count data, each with its own strengths depending on your analysis goals:

  • Total Sum Scaling (TSS): Normalizes each sample by dividing by the total number of reads; simple but sensitive to library size differences and does not handle sparsity well.
  • Rarefaction: Random subsampling to a fixed depth; useful for equalizing library sizes but can discard valuable data and introduce randomness.
  • Relative Abundance: Handles compositionality by log-transforming the ratio of each count to the geometric mean; often used in conjunction with tools like ALDEx2 or compositions package.
  • Centered Log-Ratio (CLR) Transformation: Converts counts to proportions (e.g., counts per ASV divided by total sample count); good for compositional comparisons but not suitable for abundance-sensitive metrics.
  • Variance Stabilizing Transformation (VST) from DESeq2: Reduces heteroscedasticity in count data, suitable for downstream statistical analysis.
  • Quantile or Rank Normalization: Aligns distributions across samples, mostly used in gene expression but applicable to microbiome data for certain comparisons.

Each method has trade-offs, so your choice should align with your research question and downstream statistical requirements.

Here, I present an example of Cumulative Sum Scaling (CSS), the normalization method I usually use for ASV read-count data.

2. What are Cumulative Sum Scaling (CSS)?

Cumulative Sum Scaling (CSS) is a normalization method designed to correct for differences in sequencing depth (library size) among samples while preserving meaningful variation in total abundance. Unlike relative-abundance normalization, which forces every sample to have the same total (e.g., 100%), CSS calculates a scaling factor from the cumulative sum of relatively low-abundance features, typically below a selected quantile. This reduces the influence of highly abundant taxa that may dominate particular samples and provides a more robust basis for comparing microbial community composition and abundance across samples.

3. Install R-package and example of CSS normalization


# Install and load metagenomeSeq
if (!requireNamespace("BiocManager", quietly = TRUE))
install.packages("BiocManager")

BiocManager::install("metagenomeSeq")

library(metagenomeSeq)

# Example ASV read-count table
# Rows = ASVs
# Columns = samples

asv_table <- data.frame(
  Sample01 = c(120, 45, 10, 500, 2),
  Sample02 = c(80,  30, 5,  300, 1),
  Sample03 = c(200, 60, 20, 800, 5),
  Sample04 = c(50,  15, 3,  150, 0),
  row.names = c("ASV1", "ASV2", "ASV3", "ASV4", "ASV5")
)

# Convert ASV table to data.frame
asv_read_count <- as.data.frame(asv_talbe)
	
# CSS normalization
# Create MRexperiment object
metaSeqObject <- newMRexperiment(asv_read_count)

# Calculate CSS normalization percentile
metaSeqObject_CSS  <- cumNormStatFast(metaSeqObject)

# Apply CSS normalization
metaSeqObject_CSS <- cumNorm(metaSeqObject, p = metaSeqObject_CSS)

# Extract CSS-normalized ASV table
ASV_read_count_CSS <- data.frame(
  MRcounts( metaSeqObject_CSS,
    norm = TRUE,                # norm = TRUE  -> normalized counts
    log = FALSE                 # log = FALSE  -> no log transformation
  )
)

# Display the CSS-normalized ASV table
ASV_read_count_CSS


# Check the normalization factors
# Display the CSS normalization factors calculated for each sample.
# These factors reflect differences in sequencing depth between samples.

normFactors(metaSeqObject_CSS)

4. Some important points to note

  • Use raw read counts as input: CSS should be applied to the original ASV count table, not relative abundance, percentages, or previously normalized data.
  • Check table orientation: metagenomeSeq expects ASVs/features as rows and samples as columns.
  • Remove inappropriate features first: Consider removing extremely rare ASVs (e.g., ASVs occurring in only 1–2 samples or with very low total reads) before normalization, depending on your study design.
  • Check for empty samples: Samples with zero total reads should be removed before CSS normalization.
  • Keep sample metadata separately: Make sure sample names in the ASV table exactly match the corresponding sample IDs in your environmental metadata.
  • CSS does not remove biological variation: It corrects differences associated with sequencing depth/library size; it does not make samples biologically comparable in every respect.
  • Do not confuse CSS with relative abundance: CSS does not force every sample to sum to the same total count.
  • Choose the log transformation appropriately: When using MRcounts(..., norm = TRUE, log = FALSE), the output contains CSS-normalized counts without an additional log transformation. If log = TRUE is used, the CSS-normalized counts are additionally log-transformed, which can reduce the influence of highly abundant ASVs and make the distribution less skewed. However, the choice depends on the downstream analysis; do not apply log transformation automatically if the analysis is intended to use CSS-normalized abundance values directly.
  • Keep the raw table: Always retain the original ASV count table so that the normalization can be reproduced or alternative normalization methods can be tested.
  • Check the normalization result: Compare library sizes before and after CSS and inspect whether samples with very different sequencing depths have been appropriately normalized.
